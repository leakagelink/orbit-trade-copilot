## src/lib rules
- Exchange account-type preferences use spot/futures/both metadata; owner-authenticated edits never enable futures execution or alter keys — selection is not trading authority.
- Exchange I/O goes through `src/lib/exchange-adapters.server.ts` (Web Crypto HMAC, fetch only) and indicator math lives in pure `src/lib/indicators.ts` — Workers-safe and testable.
- New backtests run `next-bar-v3` (`backtest-v3.ts`) only after `historical-data.ts` validation passes, storing provenance, splits and benchmarks in the existing result log; `backtest.ts` (v2) stays frozen and replay dispatches by simulator version — saved evidence stays reproducible and incomplete history is never simulated.
- Bot mutations and connection verification are server-authorized; engine reads bind owners, uncertain fills retain original intents, and inactive bots still manage exits — prevents browser promotion and blind order retries.
- Independent evaluations consume canonical-hashed historical evidence and remain append-only; only versioned admin-authored anchors yield experimental historical utilities, while missing validation never yields a composite or promotion — prevents agent self-grading.
- Evaluation reports retain the scoring policy snapshot and distinguish missing policy, sample floors and independent evidence; observed drawdown remains descriptive and invalid arithmetic yields no utility — keeps historical diagnostics auditable without granting trading authority.
- Paper research math is pure and forward-only, fills from completed daily bars after explicit confirmation, conservatively resolves ambiguous stops, and includes user cost assumptions — avoids historical look-ahead and fabricated live fills.
- Research allowances are atomically claimed before inference; separate immutable paper and emergency-event records never authorize orders or wallet changes — bounds usage and isolates advisory evidence.
- Independent evaluation replays frozen simulator evidence; backtest results and measured research-stage metrics are server-written append-only, and provider costs stay unknown without billing evidence — prevents recomputed fabricated ledgers and invented costs.
- New positions retain entry order IDs and quote-valued fees; spot gross PnL subtracts entry/exit fees once, with unknown legacy costs retained for reconciliation — prevents omitted opening costs.
- Binance production candles and history retry the official data-only host when the primary feed fails; testnet and signed/order endpoints never switch hosts — keeps charts available without changing venues or execution.
- Arbitrage math lives in pure `src/lib/arbitrage.ts`; authenticated highest-tier functions use `arbitrage.server.ts` for server-fetched depth and prefunded legs. Each run and both order intents are durably claimed before submission; ambiguous fills lock further runs for review, never blind retry or transfer funds. AI reviews are advisory; live execution requires user confirmation because cross-exchange orders are not atomic.
- Arbitrage reconciliation is lookup-only by durable client order IDs, with a cooling period and compare-and-set persistence; missing, open, partial or unequal fills keep the lock — prevents blind resubmission and racing active execution. Base fees adjust inventory; only quote fees are additionally deducted from actual cash flows.
- Manual trades go through `src/lib/manual.server.ts` (open/close shared by UI server fns, engine tick and emergency stop); forex/commodities run on OANDA (`oanda*` in exchange-adapters, apiKey=token, apiSecret=account ID), paper SL/TP and OANDA broker-close sync run in `manageManualPositions` each tick.
- Scalps are manual positions flagged `is_scalp` (positions + trades) with `max_hold_until`; rules live in pure `src/lib/scalping.ts`, new entries require highest-tier access and exits run through `checkManualPosition` (engine tick + owner-authenticated `checkScalps` polling) — one exit path for manual trades.
- USD-M Futures use separate `futures*.ts` and `binance-futures.server.ts` paths, dispatch by market_type, and owner-bound credentials; only one-way isolated symbols are supported; after owner limits and live opt-in pass, entries may switch the account to one-way/single-asset (only when flat with no orders) and set the symbol to isolated + requested leverage, re-reading Binance to confirm — prevents Spot/Futures confusion and mismatched broker modes.
- Binance USD-M requests go only through the frozen Testnet or Live adapter (`binance-futures-testnet/live.server.ts` via `binance-futures-core.server.ts`); each request is checked against an exact endpoint allowlist, the account's immutable environment and credentials bound at decryption (`binance-futures-env.ts`, `credential-environment.server.ts`); Testnet keys must pass a Testnet-only check before saving, and Testnet entries use fixed `futures-testnet-limits.ts` without touching production limit records — keys can never cross environments.
- Futures work runs under a per-account lease/fence with durable client IDs; risk checks and intent claims precede broker setting changes, ambiguous submits are lookup-only, partial or unverified protection is contained reduce-only, and exact order/funding evidence finalizes atomically by immutable environment — prevents duplicate exposure and mixed PnL.
- Production Futures entry requires `futures-authorization` (latest PASS for the bound account and current revision, live opt-in, not halted) at preflight, after the intent claim and immediately before submit, mirrored by the DB order gate; disabling Live needs no certification — stale or failed evidence never authorizes capital.
- The Phase 1.6 Testnet harness (`futures-harness*.ts`, `futures-faults.server.ts`, `scripts/futures-harness/`) runs only for a dedicated non-admin test account whose connections are all Testnet; fault plans and crash checkpoints are refused on production accounts, every scenario requires an unchanged production-owner fingerprint, and it never writes certification records; its preflight is read-only with GET-allowlisted exchange calls — test evidence can never authorize production capital.
- Research analyst calls stream through `aiPrimeMessageStreamed` with an auto-chosen strict report tool (the provider rejects forced tools); an invalid reply gets at most one format correction, budget-checked before sending, and provider failures are never retried — avoids connector timeouts and duplicate billing.
- Research reaches account risk only through read-only `research-risk.server.ts` → `risk-limits.server.ts` (the same `accountRiskBlock` engine.server re-exports) and prices through `yahoo-chart.server.ts`; an import-graph test forbids order-capable modules — research can never reach execution.
- Research AI calls reserve tokens atomically in the 0043 database ledger (one platform lock, single worker per run, append only while running) and settle with provider usage or the full reservation; cancel, ownership and ledger checks fail closed — concurrent runs cannot pass caps or append to closed runs.
- Forward paper trading is a pure one-closed-candle step (`paper-engine.ts`, sizing in `paper-risk.ts`) run by `paper.server.ts` on public klines only (`paper-market-data.server.ts`); each candle commits atomically through `paper_commit_bar` (cursor compare-and-set, cash reconciliation, account risk re-check) into its own append-only ledger, entry fills re-check the same account limits against the latest ledger view so a refused commit is never recomputed into the same refusal, and an import-graph test forbids order, credential, wallet, bot, Autopilot, Futures and AI modules — simulated fills can never reach real capital and interrupted ticks recompute identically.
- Engine B scalping (`scalp-intraday.ts`, `scalp-microstructure.ts`, model research in `scalp-model.ts`/`ml-logistic.ts`) and the Central Risk Engine (`central-risk.ts`, engine adapters in `central-risk-proposals.ts`) are pure: signals are proposals with no size or leverage, only `evaluateProposal` sizes them, and ACCEPT is never an execution authorization; an import-graph test forbids server, exchange, wallet and AI modules — no LLM in seconds-level decisions and no path from a signal to an order until a reviewed gate is approved.
- Futures paper (`futures-paper-engine.ts`) is a pure, separate ledger from Spot paper: every entry is sized only by `evaluateProposal` (environment paper), protection and liquidation are mark-price based, and state reconciles from its own event ledger (draft 0049 replaces the rejected 0046: the database recomputes every risk, fee, margin and P&L figure from its recorded candle, frozen config and approval rows, and fills only against a matching unexpired approval — payload builder `futures-paper-ledger-v3.ts` never sends risk or fill ids); every pending fill is re-validated with the draft ledger's own definitions (status/halt, identity, marks, daily loss, cumulative budget incl. other accounts, exposure, count, margin) and a refusal cancels with a reason code; ledger-bound candles go through `stepFuturesPaperCandle` (one account cursor, all symbols or nothing) and commit refusals through `planCommitRefusal` (bounded, never loops) — the engine can never stall on a fill the database refuses and simulated fills never reach capital.
- The 0049-aligned paper layer (`futures-paper-engine-v3.ts`) drives the byte-frozen core per symbol: expiry cancels remainders, the core's own budget is neutralized so database budgets (via `riskEngineStrategyBudget`) size acceptance, a sequential 0049 mirror re-checks every approval/fill, costs resolve with 0049 precedence, and `planLedgerRefusalV3` maps every 0049 message to a bounded code (unknown, inconsistent, repeated or ambiguous → halt). The worker (`futures-paper-worker.ts`) is port-injected, off unless `enabled: true`, has no route/cron, and its SQL lives in `futures-paper-worker-queries.ts`; candles pass `futures-paper-market-data.ts` provenance first — one budget source, payloads the database accepts, and no unattended activation.
- Central Risk shadow mode (`central-risk-shadow.ts` pure record/adapter, `central-risk-shadow.server.ts` evaluator) is imported by no order, route, cron or Autopilot path; it adapts a Futures ticket using the connection's immutable environment and a verified mark price, reads SELECT-only, never fetches production prices for Testnet, never throws, records missing or stale evidence as INSUFFICIENT_DATA (never REJECT), stores bounded error codes instead of exception text, and keeps deeply frozen records in memory only — observing can never authorize, block or resize an order.
- Lower-frequency research (`lowfreq-research.ts`, runner `scripts/lowfreq-eval/`) is pure: a pre-declared grid, next-open/trade-through fills, train-only selection, validation confirmation and a locked test scored once for survivors — NO TRADE stays the default and test data never tunes anything.
- Phase 4C modules (`ema-forward-research.ts`, `risk-data-contracts.ts`, `futures-paper-ledger-v2.ts`) are pure and imported by nothing in the app; research specs are hash-frozen (spec JSON + test) and committed before new data is scored, and `docs/phase-4c/protected-files.sha256` pins order/exchange/credential/route/migration files for an isolation test — keeps offline research and draft-ledger code out of execution paths.

- Real-order strategy identity is drafted (0047) as separate insert-only tables keyed by the entry order and captured only in the claim transaction; real orders/positions/trades are never altered or backfilled and rows without identity stay UNATTRIBUTED — attribution can never be inferred after the fact.
- Paper risk budgets nest account → Research/Scalping sub-budget → strategy (pure `account-risk-budget.ts`, mirrored by draft 0049); usage = closed losses + open + pending risk and every level is checked — independently additive strategy budgets can never exceed the central account budget. Retention rules live in pure, unenforced `retention-policy.ts`; audit records are anonymized, never deleted, on account deletion.
- The Futures paper worker's hosted connection (`futures-paper-worker-hosted.ts`, server binding `.server.ts`) is OFF by code and by an unset environment flag; it calls only six allowlisted service-only gateway functions of draft 0050 (fenced lease rows, one-statement snapshot, READ COMMITTED-only commit, provenance records that never claim verified prices), treats reply-less failures as unknown outcomes resent identically at most once, and monitors codes only — the hosted Data API cannot hold session locks, and a stale snapshot or replayed payload must never create a fill.
- Futures paper completeness (draft 0051) is enforced in the database: the commit derives the required funding charges and exits from its own book and the recorded candle (conservative intrabar order, frozen protection terms, no gaps while exposed) and refuses differences or ambiguity; the gateway commits only through it — the worker is never trusted that an event was unnecessary.
- Draft 0052 makes the database derive every Futures-paper entry fill/cancellation (claimed refusals pass only when a rolled-back trial is refused with the same code) and lets stopped accounts with exposure commit exit-only, as the worker does; the disabled signed-in worker identity (`futures-paper-worker-identity*.ts`, drafts 0053+0054) never uses the service key, and the database re-checks its current eligibility and enrollment on every call (writes lock those rows) while admins can always disable it — the worker can neither omit fills, trade after a stop, nor outlive a revocation.
- The signed-in paper worker binding runs one bounded session per tick through pure `worker-auth-session.ts` (single sign-in, verified token, call deadline below tick budget and token expiry, at most one refresh, no retries, local sign-out always, bounded codes only) over plain fetch with refused redirects, never a client library or privileged key — no long-lived tokens, hidden retries or credential logging.
